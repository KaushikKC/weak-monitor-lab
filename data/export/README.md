# data/export

Raw-data export of runs `local-main-*`, `fresh-*`, `elicited-*`, `hvf-d1-*`, `hvf-d3-*`, `hvf-calib-*` (25 run directories with a `manifest.json`; `*-summary` directories are derived and not included). No model calls were made, and no existing file in `runs/` was changed (the summarize check wrote only to new, ignored directories `runs/hvf-d1-summary-check/` and `runs/hvf-d3-summary-check/`).

- **episodes.csv** (220 rows, one per episode): `run_id` run directory; `dataset` local-main / fresh / elicited / D1 / D3 / calib; `source` dataset_source; `fixture_policy` scripted policy that produced the episode (D3 only; empty for agent episodes); `episode_id`; `seed` scenario seed; `base_scenario_id`; `split` dev/test (base-scenario hash); `submitted` true/false; `category`, `category_v2` ground-truth classes (`docs/ground_truth.md`); `exploit_attempt`, `exploit_attempt_v2`, `successful_exploitation`, `genuine_success` labels; `proxy_score` visible score; `counterfactual_proxy` JSON `{both, scope_exclusion, unsupported_completion}`; `true_progress_T`, `gap_G` (G = proxy − T); `n_actions` executed actions; `interrupted` true/false. The `_v2` fields for local-main, fresh and elicited, and T/G for the calib runs, are not stored in those runs: they were recomputed at export with the repo's own `analysis.labels_with_v2` / `gap.compute_gaps` (both reproduce the stored values on hvf-d1 exactly, 60/60).
- **judgements.csv** (2570 rows, one per monitor judgement, invalid outputs included): `run_id` monitor run directory; `episode_id` (joins episodes.csv); `monitor_model` Ollama model id or `rule-v2`; `model_digest` Ollama digest recorded at judgement time (empty for rule-v2); `prompt_variant` v1–v5 (v1 = original prompt, recorded without a variant; empty for rule-v2); `condition` A/B/C; `suspicion_score` 0–1; `category` monitor category; `cited_event_ids` `;`-separated supporting event ids; `checklist_nonempty` the pre-registered checklist rule `analysis.checklist_flag` (empty where the output has no checklist); `valid_output` true/false; `error_type` pipeline status for invalid rows (`invalid_output`); `latency_s`; `input_tokens`, `output_tokens` as reported by Ollama (empty for rule-v2). Score, category, cited ids and checklist are empty when `valid_output` is false. `truncated` (added 2026-10-22, appended as the last column; every other column is byte-identical to the original export): true when the monitor input was shortened to fit `max_input_chars`, taken from the result's recorded `input_truncation`. It is false in all 2570 rows. For rule-v2 rows it is informational only: rule-v2 reads the derived facts, not the text.
- **manifests.json** (25 entries, one per run): `run_id` run directory, `manifest_run_id` the id stored in the run's manifest (differs only for hvf-d3-fixtures, stored as `fixtures`), `command`, `dataset_source`; `git_commit` null because the pipeline did not record it, with `head_commit_by_timestamp` = latest commit on the branch with commit time ≤ `created_at` (working-tree state at run time not recorded); `timestamps` created_at, one start per session, status updated_at, final state; `params` and `config` snapshot; `models` role, provider, model id, digest, quantisation, parameter size, family, format, size, Ollama server version; `prompt_hashes` and `software` per session; `n_sessions`, `resumed` (true when there is more than one session); `derived_at_export` flags for the recomputed fields above.
- **environment.txt**: machine, OS, CPU, GPU, RAM, Python and Ollama versions, captured at export time; no user names, host names, serial numbers or keys.
- **summarize-check.txt**: verbatim stdout of `wml summarize` re-run on 2026-10-18 at commit 531a8c4 over the hvf-d1 and hvf-d3 monitor runs, one block per dataset, each headed by the exact command and followed by its exit code. Compared with the original `runs/hvf-d{1,3}-summary/results.md` (2026-10-06), the only differences are the combined-detector rows and section added in commit 779e9c6 and the resulting plot list.

## Interruptions and deviations

All interruptions affected timing only; every stopped run was continued with `wml resume`, and no completed
episode or judgement was repeated.

| When | Run | What |
|---|---|---|
| 2026-10-24 02:21 BST | ms2-e1-mon-3b-v3 | Disk watchdog stopped the driver: free disk 9.4 GB, below the 10 GB threshold then in use. Threshold lowered to 5 GB by the user |
| 2026-10-24 10:50 BST | ms2-e1-mon-3b-v3 | Disk watchdog stopped the driver: free disk 4.4 GB, swap 14 GB, from Ollama llama-server memory growth |
| 2026-10-24 13:54 BST | ms2-e1-mon-3b-v3 | Stopped by user request (the user asked B2 to run only at night) |
| 2026-10-25 00:59 GMT | ms2-e1-mon-3b-v5 | Stopped at 495/900: Ollama returned HTTP 500 "token repeat limit reached" for ep-e13b323971f0, condition A, three times; the runner treated it as an outage. See deviation 1 |
| 2026-10-26 07:18 GMT | ms2-e1-mon-8b-v5 | Stopped by user request at 226/900 (status left as "running"; resumed normally) |

From 2026-10-24 13:52 BST a memory guard (`runs/ollama-memguard.sh`, not in the repo) unloaded the Ollama model
whenever llama-server memory passed 5 GB: 105 unloads up to 2026-10-27 02:52 GMT. Each unload makes the next
call reload the model; the model digest is unchanged.

**Deviation 1 (code change during the study, commit `1b9e03e`, tests `fd51e92`).** Ollama's HTTP 500
"token repeat limit reached" is deterministic at temperature 0, so the stopped judgement failed again on every
resume. On 2026-10-25 the user chose to count it as an invalid output. Since `1b9e03e`, that error is recorded
as an empty output with finish reason `REPEAT_LIMIT` and goes through the normal repair path (one repair, then
`invalid_output`); every other 5xx is still an outage. No prompt, label, predicate, monitor or threshold
changed. Effect on the data: exactly one judgement (ms2-e1-mon-3b-v5, ep-e13b323971f0, condition A) hit
`REPEAT_LIMIT`; its repair returned a valid output, so it counts as valid with 1 repair. Runs or sessions on
code before `1b9e03e` (commit `255a950`): E1 generation, E3 fixtures, ms2-e1-mon-3b-v3, ms2-e3-mon-3b-v3 and the
first session of ms2-e1-mon-3b-v5 (judgements 1–495). All later sessions ran on `fd51e92`.

**Deviation 2 (analysis).** As described under Setup, the E1 criteria rows come from `wml intervals` on the
export, because `wml summarize` splits them by batch dir. The export script `scripts/export_runs.py` was
written for this after all monitor runs had finished.
